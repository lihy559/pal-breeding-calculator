# 帕鲁配种链计算器（本地版）

一个完全离线运行的 Palworld 配种工具，专注解决两件事：

1. **模式一 · 最短路径**：在「我已拥有的帕鲁」这个配种池里，用最少的配种次数把目标帕鲁配出来（完全不考虑词条）。
2. **模式二 · 继承稀有词条**：在你标出的「带稀有词条的帕鲁」基础上，强制让这个词条**进入配种链**并一路遗传到目标，最终得到**带该词条的目标帕鲁**。

同时内置「父母 → 子代」「子代 → 父母（可多解）」查询，以及可随时增删的已拥有帕鲁存档。

## 怎么用

1. 双击打开 **`帕鲁配种链计算器.html`**（Chrome / Edge / Firefox 都可以，不需要联网、不需要装任何东西）。
2. 切到 **「我的帕鲁」** 标签，勾选你实际拥有的帕鲁：
   - 点卡片 = 拥有 / 不拥有；
   - 可选：点卡片右下角的 **★** = 把这只加进某个词条栏目（填 `传说`、`神圣` 之类的名字，同名进同一栏）。
   - 支持按中文名 / 英文名 / 图鉴编号搜索，按属性筛选，全选 / 全不选。
3. 回到 **「配种链规划」**：选目标帕鲁 → 选模式 → 点「开始计算」。
   选了模式二时，下面会出现 4 个「词条栏目」，每栏点「+ 添加帕鲁」从已拥有列表里多选。
4. 结果会给出一份**按顺序执行**的配种步骤表、配种次数 / 世代数 / 涉及的帕鲁种类，以及最后一步的备选配方。
   （每只帕鲁只配一次，所以方案里不会有重复步骤；标紫的步骤表示那一步继承了稀有词条。）

> **勾选状态会自动记住**：你每点一次帕鲁卡片 / ★ 词条标记 / 全选 / 全不选，都会立刻写进浏览器本地存档；
> 关掉页面、关掉浏览器，下次双击打开这个 HTML，会**自动恢复上次的勾选**，并在「我的帕鲁」里显示「已自动恢复上次的存档：N 只」。
> 想备份或换电脑，用「导出存档 / 导入存档」转移 JSON 即可。

## 存档（勾选状态）

- 写入时机：每次改动（勾选 / 取消勾选 / 标词条 / 改模式 / 改目标 / 导入）立即保存，关闭页面前再兜底保存一次。
- 存储位置：浏览器 localStorage（按 `file://` 域名共享），不联网、不上传。
- 取消勾选：再点一次卡片即可取消，取消同样立刻保存；「全不选（当前筛选）」可批量取消。
- 兜底：若某个浏览器禁止 `file://` 页面写 localStorage，会在顶部提示，并退回 `window.name` 保存（刷新不丢）；
  这种情况建议直接用「导出存档」把 JSON 存到硬盘。

## 两种模式的差别

| | 模式一 · 最短路径 | 模式二 · 继承稀有词条 |
|---|---|---|
| 输入 | 已拥有帕鲁 | 已拥有帕鲁 + 最多 4 个「词条栏目」 |
| 目标 | 只要配出目标帕鲁 | 配出**并且同时带齐所填词条**的目标帕鲁 |
| 结果 | 配种次数最少的方案 | 这些带词条的帕鲁都进入配种链，词条最终汇到目标身上 |
| 代价 | 最短 | 通常更长：词条帕鲁的配种力不一定在最优路径上 |

词条模式（二合一，简洁版）：

- **4 个词条栏目**，留空即不用。**只填 1 栏 = 单条词条、多只帕鲁**（同词条的多只帕鲁会一起纳入搜索取最短，可中途换另一只抄近路）。
- **一栏可以放多只**帕鲁：例如「传说」这一栏同时放空涡龙和唤冬兽，工具会自动挑最省的那只接入链条。
- **同一只可以放进多栏**（它就是个标记），等于它同时提供这几条。
- **目标需要同时带齐**被填写的所有词条。例如「传说」和「神圣」两栏都填了，最终目标必须同时带这两条——
  实现方式是让分别带着它们的两个人配对，让子代同时继承。
- 也可以在「我的帕鲁」里给帕鲁点 ★ 快速加入栏目（同名进同一栏）。

**词条怎么传**：每一代只要**任意一只亲本**带该词条，子代就有机会继承（不需要双亲都带）。所以两个不同词条要汇到同一只身上，
只需要在某一步让分别带它们的两个人配对即可。如果工具提示「不可达」，说明配种表里没有能把这几条同时汇到目标的路线——
可以少填一栏，或者换一只离目标更近的词条帕鲁。

## 配种次数 / 世代数 是怎么算的

游戏里亲本配完不会被消耗，同一只帕鲁可以反复当亲本，所以：

- **配种次数** = 需要**新配出多少只不同的帕鲁**（= 要产多少颗蛋）。同一只帕鲁只会算一次，之后可以同时喂给多条支路，
  所以方案里**不会出现重复的配方**（网上那些把同一只配种配好几遍的算法，都假设亲本被消耗了）。这是总工作量。
- **世代数** = 依赖链的层数。已拥有 = 第 0 层；某只配出来的帕鲁，层数 = 两只亲本里较深的那只 + 1。
  相当于「同时开多个牧场，最少几轮能全部配完」。

两者只在链条有分支时才不同。实测你的那种池子（7 只入门帕鲁 → 阿努比斯）：

| 优先目标 | 配种次数（蛋数） | 世代数 |
|---|---|---|
| 最少配种次数（默认） | **13** | 10 |
| 最少世代数 | 15 | **6** |

也就是说：默认模式少配 2 次，但要多等几轮；如果你开了多个牧场想尽快出结果，选「最少世代数」。

模式二说明：游戏里子代词条是从父母双方词条中**按概率**继承的（并非 100%，且最多 4 条）。本工具保证的是**路线结构正确**——每一代都让带词条的亲本参与配种，使子代有机会继承。实际没出就重复配同一对；想让概率更高，尽量让词条帕鲁和词条少的「干净」帕鲁配对。

## 配种公式（逆向结论）

网站上的配种表并不是实时算出来的，而是预先算好的对照表。逆向出来的规则是：

1. **同种自交**：`A + A = A`。
2. **特殊固定配方优先**：例如 `Mossanda_Lux + Mossanda_Lux = Shroomer_Noct`、变体帕鲁（`Mau_Cryst`、`Fuack_Ignis` 等）都有各自的固定配方。
3. **其余组合按配种力 CombiRank**：
   `中值 = floor((配种力A + 配种力B + 1) / 2)`，子代 = 配种力最接近中值的帕鲁；
   距离相同则由游戏内的重复优先级（`CombiDuplicatePriority`）和亚种标识决定。
4. **只能自交的帕鲁**（空涡龙、唤冬兽、圣光骑士、混沌骑士、贝菈诺娃系列、暴电熊、百合女王、异构格里芬等 27 只）：除自交外没有任何配方。

因为第 3 条的平局优先级不在公开数据里，纯公式复现网站表约有 92% 吻合率；**本工具不重新推导公式，而是直接内嵌完整的 299 × 299 配种表（44850 组，含全部特殊配方），所以结果与 pals.wiki 完全一致。**

## 目录结构

```
帕鲁配种链计算器.html   ← 成品（自包含，双击即用）
icons/                  ← 299 个帕鲁图标（来自 pals.wiki，离线可用）
preview/                ← 浅色主题下的界面预览图（配种链规划 / 我的帕鲁 / 模式二结果）
src/
  core.js               ← 计算核心：查表 + 最少配种次数搜索（两种模式共用）
  app.template.html     ← 界面模板（成品由它 + 数据生成）
data/
  pals.json             ← 归一化后的帕鲁数据（名字 / 编号 / 属性）
  pal-data.json         ← 成品同款数据（含 base64 配种表，供测试使用）
  raw/                  ← 原始抓取文件（pals.wiki 的配种表 / 帕鲁数据、palcalc 参考实现）
tools/
  build.mjs             ← 生成成品 HTML
  gen-icons.mjs         ← 生成图标下载任务
  check-html.mjs        ← 成品静态检查（语法 / DOM id / 图标齐全）
  test-core.mjs         ← 算法测试（含与独立参考实现交叉验证）
  test-ui.mjs           ← 端到端测试（用最小 DOM 跑完整界面脚本）
  spot-check.mjs        ← 若干真实场景的抽样体检
  research/             ← 当年逆向公式用的探索脚本（存档用途）
```

## 重新构建 / 测试

需要 Node.js（本仓库用 v24 验证）。无需安装任何依赖。

```powershell
node tools/build.mjs        # 用 src/ + data/raw/ 重新生成成品 HTML
node tools/check-html.mjs   # 静态检查
node tools/test-core.mjs    # 算法测试（39 项）
node tools/test-ui.mjs      # 界面端到端测试（18 项）
node tools/spot-check.mjs   # 场景抽样
```

## 已知限制

- **词条遗传是概率事件**：工具算的是路线结构，不模拟「这一次配种出不出词条」的随机性。
- **不做性别 / IV / 被动技能数量**的规划，也不考虑捕捉与商人。
- **多次用到同一只帕鲁时，需要多只**：步骤表里同一配方的重复出现，代表那次配种要再做一遍（因为一颗蛋只出一只帕鲁）。
- 数据来源为 pals.wiki 当前导入的配种表；游戏更新后需要重新抓取并用 `tools/build.mjs` 重建。
